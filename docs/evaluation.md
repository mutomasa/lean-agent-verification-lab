## 観察

- **json モード**（構造化出力 + few-shot）: 「残高50円なのに200円振り込もうとしています」で `none` を選び、理由欄で自ら「安全ではありません」と判定した。ツール対象外は `ERROR` として扱い、判定として表示しないため安全側に倒れる。
- **tools モード**: ツール選択は全問正解だが、**引数の誤抽出**（送金額 120→20、要求にない需要 60 の追加）が 25% のケースで発生し、根拠チェックの警告が出た（#7）。ツール選択率だけでは品質を評価できない。
- **説明文**: VIOLATION を「証明できなかった」と説明するケースが残り、整合チェックで定型文に置換された（#8）。
- few-shot に「変更なしで現状を検証」「稼働上限の変更」を追加したことで、json モードの判定一致率は 83% → 92% に改善した。

## 結論

既定は **json モード** とする（誤った引数で実行し、見かけ上 PASS になるリスクが小さいため）。どちらのモードでも最終判定は Lean の結果のみを正とする。
